# Отчёт по итогам автоматизации

## Что было запланировано и что реализовано

В рамках дипломного проекта была запланирована и выполнена автоматизация тестирования веб-сервиса **«Путешествие дня»** (`aqa-shop.jar`):
* Поднято локальное тестовое окружение в Docker (СУБД MySQL 8.0 и симулятор банковских сервисов).
* Реализован проект автотестов на базе Java 11, Gradle, JUnit 5, Selenide, Lombok и JavaFaker.
* Применён паттерн Page Object и подготовлены вспомогательные классы (`DataHelper`, `SQLHelper`) для генерации тестовых данных, очистки таблиц перед каждым тестом и проверки статусов операций в базе данных (`APPROVED` / `DECLINED`).
* Автоматизированы **15 тест-кейсов** для проверки оплаты тура по дебетовой карте (`PaymentFormTest`).
* Настроено формирование отчётов о прохождении тестов с использованием **Allure Report** и встроенного отчёта **Gradle**.
* По итогам тестирования оформлены отчёты о выявленных дефектах в GitHub Issues.

## Причины, по которым что-то не было реализовано

* **Автоматизация второй формы покупки тура и API-тестов:** по условиям задания требуется автоматизировать одну форму оплаты, тогда как проверка второй формы и написание API-тестов относятся к дополнительным необязательным пунктам. Основные усилия были сосредоточены на качественной проработке UI- и DB-сценариев для выбранной формы.
* **Подключение Report Portal и CI:** в качестве системы отчётности выбран **Allure Report** (совместно с отчётами Gradle) в соответствии с условием задания («Gradle, Allure или Report Portal»). Локальный запуск Report Portal требует поднятия дополнительных тяжёлых сервисов и значительных системных ресурсов, поэтому для локального запуска и проверки проекта использован более лёгкий вариант на базе Allure. Интеграция с CI также являлась необязательной частью.

## Сработавшие риски

1. **Настройка окружения и запуск компонентов:** потребовалось дополнительное время на согласование версий окружения, браузера и драйверов, а также на отладку взаимодействия тестов с базой данных в Docker.
2. **Неоднозначность ожидаемого поведения при отсутствии подробной документации:** часть правил валидации полей и логики отображения уведомлений уточнялась в ходе исследовательского тестирования и анализа работы приложения.
3. **Выявление дефектов в работе приложения:** обнаруженные ошибки потребовали перепроверки кейсов и оформления отдельных баг-репортов.
