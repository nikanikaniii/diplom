# Автоматизация тестирования веб-сервиса «Путешествие дня»

Курсовой проект по модулю «Автоматизация тестирования» для профессии «Инженер по тестированию». Репозиторий содержит набор автоматизированных UI- и DB-тестов для проверки функционала оплаты тура по дебетовой карте. Проект реализован на базе Java 11, Gradle, JUnit 5, Selenide, WebDriverManager, Allure и СУБД MySQL 8.0.

## Начало работы

Ниже приведено руководство по развёртыванию локальной копии проекта и запуску тестового прогона.

### Prerequisites

Для работы с проектом на локальном компьютере требуется наличие следующего программного обеспечения:
* **Git** — для клонирования репозитория.
* **JDK 11** — для сборки проекта и выполнения тестов.
* **Docker Desktop** — для запуска контейнеров с базой данных и симулятором банковских сервисов (перед стартом тестов приложение должно быть запущено).
* **Google Chrome** — браузер, используемый при выполнении UI-сценариев.

### Установка и запуск

1. **Клонирование репозитория**
   ```bash
   git clone https://github.com/nikanikaniii/diplom.git
   ```

2. **Переход в директорию проекта**
   ```bash
   cd diplom
   ```
   *(Имя директории совпадает с названием репозитория на GitHub).*

3. **Запуск контейнеров окружения в фоновом режиме**
   ```bash
   docker-compose up -d
   ```

4. **Запуск тестируемого приложения (`aqa-shop.jar`)**
   ```bash
   java -jar artifacts/aqa-shop.jar
   ```
   После запуска приложение доступно по адресу `http://localhost:8080`.

5. **Запуск автотестов** (выполняется в новом окне терминала из директории проекта)
   ```bash
   ./gradlew clean test
   ```

6. **Формирование и просмотр отчёта Allure**
   ```bash
   ./gradlew allureServe
   ```

#### Проверка данных в СУБД MySQL

Перед началом каждого тестового сценария таблицы базы данных очищаются автоматически с помощью метода `SQLHelper.cleanDatabase()` для обеспечения независимости проверок. При необходимости просмотреть итоговые записи в СУБД после выполнения конкретного кейса рекомендуется запускать соответствующий тест отдельно через команду ./gradlew test --test "...", чтобы последующие сценарии не перезаписали состояние таблиц.
